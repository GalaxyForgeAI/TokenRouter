# TokenRouter 炬枢 · 製品概要

> TokenRouter（炬枢）—— 企業向けプライベート AI ゲートウェイ。
> モデル呼び出しをひとつの管理された入口に集約します。**すべての呼び出しが制御・追跡・帰属可能**に。

## TokenRouter が必要な理由

企業が AI を導入すると、すぐに 4 つの問題に直面します。

| 問題 | 症状 |
|---|---|
| **アクセス分散** | チームごとに OpenAI / Anthropic / Gemini / 国産モデルを個別接続し、キーが乱立 |
| **ガバナンス不在** | 誰がどのモデルを呼べるか、プロジェクト予算、上流への負荷に統一ポリシーがない |
| **コストの見えにくさ** | 月末請求をチーム・プロジェクト・モデル・コストセンターに帰属できない |
| **監査の欠如** | インシデント後に「誰が、いつ、どのキーで、何を呼んだか」が追えない |

TokenRouter は **統一アクセス → ポリシーガバナンス → 使用量帰属 → 完全監査** の 4 つをひとつのセルフホスト型ゲートウェイで解決します。

## コア機能

### 統一アクセス

- OpenAI 互換 API: `/v1/chat/completions`、`/v1/responses`、`/v1/embeddings`、`/v1/images/*`
- Anthropic Messages API: `/v1/messages`、`/v1/messages/count_tokens`
- ネイティブアダプタ: OpenAI、Azure OpenAI、Anthropic、Gemini、DeepSeek、Qwen、Codex サブスクリプション、ローカル vLLM / Ollama
- **150+ プロバイダーテンプレート**、カスタム OpenAI 互換上流も対応

### ポリシーガバナンス

- モデルカタログ + ルーティングポリシー（優先度・重み・フェイルオーバー順・経路ヘルス診断）
- プロジェクト単位 API キー管理（チーム所有・メンバー権限・クォータ・並行制御）
- クォータ変更・機密操作の承認フロー
- セキュリティポリシー（コンテンツ安全、プロキシ出口、ID ソース OAuth/OIDC、RBAC、監査）

### 使用量とコスト

- **ユーザー・プロジェクト・チーム・モデル・コストセンター** の 5 次元で帰属
- トークン明細（入力/出力/キャッシュ/推論）とコスト明細付きリクエストログ
- エグゼクティブダッシュボード（部門比較、Top モデル、コスト比率、トレンド）

### 可観測性とセキュリティ

- ヘルスチェック、アラートルール、通知チャネル
- データベースバックアップ（SQLite / PostgreSQL）と状態監視
- 管理操作監査（誰がどの設定を変更したか）

## 3 つのロール

| ロール | 焦点 | 主な作業 |
|---|---|---|
| **一般ユーザー** | モデル利用 | 利用可能モデル検索、プロジェクトキー作成、API 呼び出し、個人使用量確認 |
| **チームリーダー** | プロジェクト管理 | プロジェクトスペース、メンバー、キー、チームレポート、コスト帰属 |
| **管理者** | プラットフォーム運用 | プロバイダー、モデルカタログ、ルーティング、ID ソース、RBAC、監査、コスト制御 |

## アーキテクチャ

- **バックエンド**: Go 1.26、SQLite（デフォルト）/ PostgreSQL
- **フロントエンド**: Next.js 16 + React 19、3 言語（en/zh/ja）
- **デプロイ**: Docker Compose、リバースプロキシ対応
