# TokenRouter 炬枢 · 产品概述

> 炬枢（TokenRouter）—— 企业私有化 AI 网关。
> 把散落各处的模型 API 统一收口到一个受治理的入口：**每一次调用都可控、可追踪、可归因**。

## 为什么需要炬枢

企业接入 AI 能力后很快会遇到四个问题：

| 问题 | 表现 |
|---|---|
| **接入散乱** | 不同团队各自接 OpenAI / Anthropic / Gemini / 国产模型，Key 满天飞，无法统一管理 |
| **治理缺失** | 谁能调什么模型、一次能花多少钱、高并发会不会打爆上游——没有统一策略 |
| **成本黑洞** | 月底账单无法归因到团队、项目、模型、成本中心 |
| **审计空白** | 出了安全事故，查不到"谁、在何时、用什么 Key、调了哪个模型、发了什么" |

炬枢用一个自托管网关解决全部四个问题：**统一接入 → 策略治理 → 用量归因 → 全程审计**。

## 核心能力

### 统一接入

- **OpenAI 兼容 API**：`/v1/chat/completions`、`/v1/responses`、`/v1/embeddings`、`/v1/images/*`
- **Anthropic Messages API**：`/v1/messages`、`/v1/messages/count_tokens`
- 原生适配：OpenAI、Azure OpenAI、Anthropic、Gemini、DeepSeek、Qwen、Codex 订阅、本地 vLLM / Ollama
- **150+ Provider 模板目录**，自定义 OpenAI 兼容上游一键接入

### 策略治理

- **模型目录 + 路由策略**：优先级、权重、故障转移顺序、路由健康诊断
- **项目级 Key 管理**：团队归属、成员权限、配额、并发控制
- **审批流**：配额提升、敏感操作审批留痕
- **安全策略**：内容安全策略（CSP）、代理出口、身份源（OAuth/OIDC）、RBAC、审计追踪

### 用量与成本

- 用量归因到**用户、项目、团队、模型、成本中心**五维
- 请求日志 + Token 明细（输入/输出/缓存/推理）+ 成本明细
- 管理看板：部门 Token 消耗对比、Top 模型、成本占比、趋势

### 可观测与安全

- 健康检测、告警规则、通知渠道
- 数据库备份（SQLite/PostgreSQL）、数据库状态监控
- 后台操作审计（谁改了什么配置）

## 三种角色

| 角色 | 关注面 | 主要工作 |
|---|---|---|
| **普通用户** | 用模型 | 找可用模型、创建项目 Key、调用 API、查看个人用量 |
| **团队负责人** | 管项目 | 项目空间、成员、Key、团队报表、成本归因 |
| **平台管理员** | 管平台 | Provider 渠道、模型目录、路由策略、身份源、RBAC、审计、成本控制 |

## 技术架构

```
┌─────────────────────────────┐
│  管理控制台（Next.js 16）     │  ← 角色感知导航、全局搜索、双主题、API 文档
└──────────┬──────────────────┘
           │ /api/admin/*（JWT）
┌──────────▼──────────────────┐
│  网关核心（Go 1.26）          │  ← 认证鉴权、路由策略、配额、审计、用量记录
│  /v1/chat/completions 等     │
└──────────┬──────────────────┘
           │ 路由（优先级/权重/故障转移）
┌──────────▼──────────────────┐
│  Provider 渠道（上游模型）     │  ← OpenAI/Anthropic/Gemini/国产/本地
└─────────────────────────────┘
```

- **后端**：Go 1.26，SQLite（默认）/ PostgreSQL
- **前端**：Next.js 16 + React 19，中/英/日三语
- **部署**：Docker Compose 一键起，支持反向代理
